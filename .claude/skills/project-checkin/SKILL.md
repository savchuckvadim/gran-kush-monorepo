# Project Check-in — Gran Kush

Ты проводишь регулярный чек-ин по проекту. Цель: напомнить пользователю о проекте, собрать полную картину «что нового / что в работе / что дальше», обсудить и приступить к работе. Общайся на русском.

## Шаг 0 — Уведомление

Сразу отправь PushNotification: короткое напоминание вида «Чек-ин Gran Kush: собираю состояние проекта и Notion, зайди обсудить план». Затем продолжай сбор данных, не дожидаясь ответа.

## Шаг 1 — Состояние репозитория

Собери (можно параллельно):
- `git status` + текущая ветка, `git log --oneline -10`
- `git branch -a --sort=-committerdate` — над чем работали недавно
- незакоммиченные изменения, если есть

## Шаг 2 — Состояние задач в репо

- Прочитай `documentation/tasks/multitenant.md` — основной чек-лист multitenant.
- Учитывай: док может отставать от кода. Известные реальные пробелы (на 2026-07-14): presence не скоупится по porталу (cross-tenant дыра в manual check-in/out и getSession), StorageFile.portalId не используется кодом, нет e2e-тестов изоляции, apps/web без auth middleware и без динамической формы регистрации, subscription guard отдаёт 403 вместо 402.
- Другие бэклоги: `documentation/crm/FLEXIBLE_CRM_DOMAIN_TASKS.md`, `documentation/crm/CRM_IMPLEMENTATION_PLAN.md`, `documentation/правки.md`.

## Шаг 3 — Notion

Через Notion MCP (инструменты `notion:*`, при необходимости загрузи их через ToolSearch):
- Открой страницу проекта CRM: page id `36b355b062ad8152aab4fa9d8d519281` (https://app.notion.com/p/CRM-36b355b062ad8152aab4fa9d8d519281) и связанную базу задач.
- Поищи (search) свежие записи/задачи/заметки по проекту: что добавлено или изменено с прошлого чек-ина, какие потребности/идеи записаны.
- Если инструменты Notion недоступны — сообщи пользователю, что MCP не подключён в этой сессии (`claude mcp list` для диагностики), и продолжай чек-ин без Notion.

## Шаг 4 — Сводка и план

Выведи пользователю компактную сводку:
1. **Где остановились** — ветка, последние коммиты, незавершённое.
2. **Что нового в Notion** — новые задачи/заметки/потребности.
3. **Предложение**: 2–3 конкретные задачи-кандидата на сегодня (с приоритетом: сначала дыры изоляции данных и auth, затем функциональность), для каждой — предлагаемое имя ветки вида `fix/presence-portal-scope`, `feat/web-auth-middleware` и оценка объёма.

## Шаг 5 — Обсуждение и старт работы

- Обсуди с пользователем, что берём. Используй AskUserQuestion с задачами-кандидатами, если он не ответил текстом.
- После выбора: создай ветку от `main` (или от той, которую скажет пользователь), зафиксируй договорённость (что делаем, definition of done) и приступай к реализации.
- Если договорились о новых задачах, которых нет в доках — предложи дописать их в `documentation/tasks/` и/или в Notion.
- Если пользователь не отвечает — оставь сводку как итоговое сообщение и не начинай изменения кода без подтверждения.
