# Project Check-in — PafPaf

Ты проводишь регулярный чек-ин по проекту. Цель: напомнить пользователю о проекте, собрать полную картину «что нового / что в работе / что дальше», обсудить и приступить к работе. Общайся на русском.

Продукт — **PafPaf**: облачная CRM для клубов по подписке и сайт `paf-paf.app`. Бренд Gran Kush закрыт, Nagual — запасная концепция. Репозиторий пока называется `gran-kush-monorepo`.

## Шаг 0 — Уведомление

Сразу отправь PushNotification: короткое напоминание вида «Чек-ин PafPaf: собираю состояние проекта и Notion, зайди обсудить план». Затем продолжай сбор данных, не дожидаясь ответа.

## Шаг 1 — Состояние репозитория

Собери (можно параллельно):
- `git status` + текущая ветка, `git log --oneline -10`
- `git branch -a --sort=-committerdate` — над чем работали недавно; какие ветки не запушены и не влиты в `main`
- незакоммиченные изменения, если есть

## Шаг 2 — Прод

- Деплой: push в `main` → GitHub Actions «Deploy» собирает образы → в Dokploy жмут Deploy вручную (`infra/dokploy/README.md`). Прогоны смотри без gh: `https://api.github.com/repos/savchuckvadim/gran-kush-monorepo/actions/runs?branch=main&per_page=4`.
- Сверь, что на проде то, что в `main`: например, ведут ли кнопки тарифов на `https://paf-paf.app/es/precios` в CRM. Если образы собраны, а прод старый — напомни нажать Deploy.

## Шаг 3 — Состояние задач в репо

- Основной чек-лист — `documentation/tasks/pafpaf-launch.md` (TASK-5xx, решения владельца, порядок веток). Смотри статусы `[ ]` / `[~]` / `[x]` и раздел «Порядок работ».
- Док может отставать от кода: перед тем как предлагать задачу, проверь код.
- Смежные бэклоги: `documentation/tasks/security-audit.md`, `scaling-roadmap.md`, `rls-postgres.md`.

## Шаг 4 — Notion

Через Notion MCP (инструменты `notion-*`, при необходимости загрузи их через ToolSearch):
- Страница проекта: page id `36b355b062ad8152aab4fa9d8d519281` (HQ → Projects).
- База Tasks: `collection://088aed58-8a1f-4b5f-bb2d-9833f247bab0`, Inbox: `collection://9559c8eb-77a1-4a9b-9766-50a261383d46`. Фильтр по связи `Project` в rows-режиме ненадёжен — отбирай задачи проекта по полю `Project` в ответе.
- Что добавлено или изменено с прошлого чек-ина: новые задачи, заметки, идеи, записи маркетинговых кронов на странице проекта.
- Если инструменты Notion недоступны — сообщи, что MCP не подключён в этой сессии (`claude mcp list` для диагностики), и продолжай без Notion.

## Шаг 5 — Сводка и план

Выведи пользователю компактную сводку:
1. **Где остановились** — ветка, последние коммиты, что не запушено или не влито, что на проде.
2. **Что нового в Notion** — новые задачи, заметки, потребности.
3. **Предложение**: 2–3 конкретные задачи на сегодня из `pafpaf-launch.md`. Приоритет: сначала дыры в auth и изоляции данных, затем P0 для первой офлайн-продажи (биллинг, бренд в письмах и UI), затем P1 для продаж через сайт. Для каждой — имя ветки из плана (или вида `feat/billing-plans-trial`) и оценка объёма.

## Шаг 6 — Обсуждение и старт работы

- Обсуди с пользователем, что берём. Используй AskUserQuestion с задачами-кандидатами, если он не ответил текстом.
- После выбора: создай ветку от `main` (или от той, которую скажет пользователь), зафиксируй договорённость (что делаем, definition of done) и приступай к реализации.
- Новые задачи, которых нет в плане, предложи дописать в `documentation/tasks/pafpaf-launch.md` и/или в Notion.
- Если пользователь не отвечает — оставь сводку как итоговое сообщение и не начинай изменения кода без подтверждения.
