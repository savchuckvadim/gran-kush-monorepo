## Коротко

1. **QR сломали наши же изменения, дважды.**
   - С 16–22.07 (`5b1db29`, `1762e7f`) API требует клуб в заголовке `X-Portal-*`, а кабинет его не шлёт
     (`apps/web/modules/shared/api/api.ts:8-11`). `/cabinet/qr-code` и `/cabinet/presence/*` отвечают
     400 «Missing portal» — QR и визиты не загружаются ни у кого (проверено на проде).
   - С 28.03 (`2b4ce9b`) в QR зашита ссылка `crm…/{locale}/scan?code=`, а такой страницы в CRM больше нет.
     Камера телефона открывает 404. Встроенный сканер CRM сам переходит по этой ссылке
     (`QrScannerDialog.tsx:126-135`) и тоже уходит на 404. Работает только ручной ввод кода.
   - Плюс: статус «в клубе» всегда «нет» (контракт `/cabinet/presence/status` не совпадает), перевыпуск не гасит
     старый QR, QR не выпускается сам (новый участник видит красное «обратитесь к администратору»),
     код очень плотный (версия 24 на уровне H).
   - QR работал на старом проде `el-gran-kush.ru` весной 2026. Кабинет на `club.paf-paf.app` включён
     14–15.10 уже в сломанном виде.
2. **Каталога товаров в кабинете не было ни в одном коммите** — товары были только в CRM. API
   `/cabinet/catalog` и `/cabinet/orders` есть с марта, но UI их не вызывал. Это новая функция, не регресс.
   Гейта «только внутри клуба» и видимости по флагам нет и в API (`isMemberPresent` нигде не вызывается).
3. **Участник другого клуба открывает ссылку клуба B.** Страница ссылки анонимная, сессию не видит.
   Аккаунт с паролем вводит тот же пароль и сразу вступает, а клуб B автоматически получает все его
   документы. Аккаунт только с Google получает членство «ждёт согласия» и письмо «задайте пароль»;
   повторный вход через Google это членство не подтверждает.
4. **Google.** Обычный вход в CRM и кабинет работает, в том числе на старых аккаунтах: Google молча
   привязывается по подтверждённому email. Не работает всё, где нужен контекст: ссылки, приглашения,
   согласие, регистрация клуба; после входа в кабинет человек попадает на лендинг. State не привязан
   к браузеру (возможен login-CSRF), нет PKCE и nonce, нет входа по id_token для мобильных.
5. **Сотрудник.** Вход и выбор клуба работают. Принять приглашение через Google нельзя; аккаунт без
   пароля получает 409 и письмо «задайте пароль». Существующий аккаунт (участник где-то) не может
   завести клуб: `/platform/portals/register` отвечает 409 на любой существующий email (TASK-508);
   Google в CRM ведёт такого человека в петлю «регистрация клуба → 409». «Добавить сотрудника» молча
   прикрепляет любой существующий аккаунт без письма и согласия.
6. **Почему регистрация клуба не берёт данные Google.** Callback передаёт в форму только `?email=` в
   адресе, без доказательства от Google. Форма требует пароль, аккаунт создаётся с неподтверждённой
   почтой, Google к нему не привязывается, имя и фамилия из Google отбрасываются ещё в клиенте
   (`GoogleProfile` хранит только sub, email, email_verified, name). Кнопки Google на странице
   регистрации нет.
7. **Как строим.** Кабинет — дерево маршрутов внутри `apps/crm`, `club.paf-paf.app` — второй домен того
   же контейнера (вариант A ниже). `apps/web` после переноса удаляется.

### Схема маршрутов (проверена по коду Next 16 и next-intl)

Внутреннее дерево — `apps/crm/app/[locale]/m/...`. На хосте `club.` proxy переписывает видимый путь
во внутренний; в адресной строке и ссылках внутренний префикс не появляется.

| Видимый путь на club. | Внутренний | Что там |
|---|---|---|
| `/{l}` | `m/page` | дом: мои клубы, приглашения клубов |
| `/{l}/auth/{login,register,forgot-password,reset-password,confirm/[token],confirm-email}` | `m/auth/*` | вход и регистрация участника (пути из писем не меняются) |
| `/{l}/join/[token]` | `m/join/[token]` | та же страница ссылки, плюс «вступить как …» |
| `/{l}/me/*` | `m/me/*` | аккаунт: паспорт, профиль, клубы, входы, настройки |
| `/{l}/{club}/*` | `m/[portal]/*` | клуб: QR, присутствие, витрина, заказы |
| `/{l}/consent/[token]` | `m/consent/[token]` | по желанию, та же страница согласия |

Условия, без которых не заработает:

- хост брать из `x-forwarded-host ?? host` (первый элемент): в standalone `nextUrl.host` — это `0.0.0.0:3000`;
- rewrite делать **после** next-intl и переносить его заголовки (`NextResponse.rewrite(url, { headers: intlRes.headers })`),
  иначе серверные `getTranslations()` откатятся на `en`; адрес назначения — от `request.nextUrl.clone()`;
- ветку club. ставить до проверки CRM-кук (`apps/crm/proxy.ts:46-57`); старые пути кабинета
  (`/profile/*`, `/clubs/*`, `/about-us`, `/contacts`) — 308 на новые; на crm. `/{l}/m/**` — 404;
- `me` добавить в `NON_PORTAL_SEGMENTS`; в API — список зарезервированных slug одной константой с CRM:
  `auth, join, consent, home, scan, profile, clubs, about-us, contacts, api, admin, crm, www, static, public,
  login, register, invite, logout, docs, account, settings` (перед включением проверить БД прода);
- две сессии в одном бандле: `refreshPromise` в `packages/api-client/src/auth/api-auth.refresh-helper.ts:6`
  общий на модуль — разделить по типу клиента; второй клиент `$lkApi` (`ApiAuthType.SITE` + `getPortalSlug`);
  ключи react-query начинать с принципала; убрать `queryClient.clear()` целиком (3 места); ключ «me»
  `['auth','current']` сейчас совпадает у сотрудника и участника; `MemberAuthProvider` по `/cabinet/auth/me`;
  запрет импорта CRM-`$api` в дереве кабинета (eslint);
- проверить на стенде: реальный `x-forwarded-host` за Cloudflare и Traefik, чтение runtime env в proxy,
  куки на поддомене в локальной разработке.

### Участник

| Ситуация | Как должно быть |
|---|---|
| Новый человек по ссылке клуба | Как сейчас + кнопка Google + шаг «паспорт» (загрузить или взять из аккаунта) |
| Вошедший участник клуба A открывает ссылку клуба B | Страница видит сессию: «Вступить как …» одним нажатием, выбор документов для показа. Учитываются лимит ссылки, `registrationLinkId`, prefill (`POST /cabinet/reg-links/:token/join`) |

| Аккаунт только с Google | Вступает сессией или через Google; писем «задайте пароль» не получает |
| Клуб добавил существующий аккаунт в CRM | Всегда «ждёт согласия» (кроме нового аккаунта). Подтверждение — в кабинете по сессии, ссылка из письма остаётся запасной (пароль или Google) |

| Несколько клубов | Клуб в URL `/{l}/{club}/…`, переключатель по `/cabinet/portals`, у каждого клуба свой QR |

### Сотрудник

| Ситуация | Как должно быть |
|---|---|
| Приглашение | Принять паролем, текущей сессией (CRM или кабинет) или Google, если email совпадает. Страница приглашения переведена, видит сессию |
| Существующий аккаунт заводит клуб | «+ Новый клуб» в переключателе, выборе клуба и меню аккаунта (TASK-508). На форме регистрации 409 превращается в «войдите, чтобы создать клуб» |

### Google

- Одна кнопка с контекстом для CRM и кабинета: `intent` (login, join_link, accept_invite, register_club,
  consent), `returnTo` из белого списка путей, токен ссылки или приглашения, `plan`, `portalSlug`.
- На `/start` — HttpOnly-кука с nonce и PKCE; в callback сверка и удаление. State подписывать
  отдельным ключом. Ошибки — в лог и с отдельными кодами.
- Регистрация клуба через Google: подписанный тикет (`sub`, email, given/family name), владелец без
  пароля, почта подтверждена, Google привязан в той же транзакции, имя и фамилия подставлены, `plan`
  сохраняется. Для существующего аккаунта — клуб на него же (TASK-508).
- В профиле: список входов, привязка и отвязка Google, «задать пароль» для Google-only.
- Мобильные: `POST …/mobile/auth/google { idToken }` — когда дойдём до приложения.

### Внутри и снаружи клуба

Правило проверяет сервер, кабинет только показывает режим по `GET /cabinet/context`.

- Всегда (членство подтверждено): QR, история визитов, мои заказы, паспорт, клубы.
- Каталог и заказ: согласие подтверждено + статус участника `approved` + открытая сессия присутствия
  не старше N часов (настройка клуба). Отказ — 403 с кодом: `presence_required`, `membership_not_approved`,
  `consent_pending`, `ordering_disabled`.
- Настройки клуба: каталог и заказ — выкл / только внутри / всегда; самовступление; кто может заказывать;
  потолок сессии; время авто-выхода.

### QR v2

- Короткий непрозрачный токен (в БД — хеш) вместо 422-символьного шифртекста в URL, уровень M,
  всегда тёмный на светлом, срок виден, экран не гаснет (wake lock).
- Перевыпуск гасит старый код. QR выпускается сам при активации членства, истёкший продлевается.
- Сканер CRM разбирает код на месте и переходит только на свой домен. Для камеры телефона —
  `/{l}/{club}/scan?code=` на crm. (или голый код — по решению, вопрос 2).
- Скан с явным действием (вход или выход, 409 при расхождении), сотрудник пишется отдельно на вход и
  выход, повторное подтверждение идемпотентно.

   сделать после витрины.
