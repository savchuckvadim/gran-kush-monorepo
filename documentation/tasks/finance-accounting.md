# Финансы и учёт: от «мёртвого» блока к отчётности клуба и студии

Дата: 2026-10-20. Ветка `main`, HEAD `6273822`. Нумерация продолжает
[events-realtime](events-realtime.md) (TASK-795). Решения Вадима 2026-10-20: данные чувствительные —
шифровать; налог в товарах (по умолчанию входит в цену, для части услуг — сверху); полный учёт для
сдачи отчётности клуба по законодательству ЕС/Испании; сразу заложить студии (autónomo и SL): доходы,
расходы, налоги, декларации, планирование расходов; реквизиты организации; «серьёзно, но не перегружать».

Требования по итогам исследования (закон, управленческий учёт, импорт таблицей, референсы Quipu и
Holded) — [finance-requirements](finance-requirements.md). Уточнение Вадима 2026-10-20: **издержки
нужны сразу, с загрузкой таблицей и примером таблицы для скачивания; не усложнять.**

## Что есть

- API `/crm/finance/*`: проводки (список, карточка, ручное создание) и три отчёта (summary, by-type,
  by-date), права `finance.read` / `finance.write`, скоуп портала, идемпотентный источник
  (`sourceType`, `sourceId`, уникальный индекс). Модель `FinancialTransaction`: тип, направление, сумма,
  валюта, способ оплаты, дата, описание, заметки, связь с заказом.
- CRM: страница `crm/finance` из трёх виджетов (сводка, по типам, таблица).
- **Почему мёртвый**: проводки никто не создаёт — заказы в финансы не пишут (в `orders` нет ни одной
  ссылки на `finance`), оплата заказа меняет только `paymentStatus`. Расходов, категорий, налогов,
  контрагентов, документов, периодов и планов нет. Всё в открытом виде.
- Шифрование: `EncryptionService` (AES-256-GCM, `ENCRYPTION_MASTER_KEY`) — для номеров документов и
  QR. Пароли — bcrypt-хэш, это не шифрование: их не нужно читать обратно, финансы — нужно.

## Решение по шифрованию

**Серверное envelope-шифрование, а не end-to-end** (вариант «попроще», Вадим 2026-10-20).

- У портала свой ключ данных (DEK, 32 байта), завёрнутый мастер-ключом (`ENCRYPTION_MASTER_KEY`, KEK);
  хранится в `portal_data_keys (portal_id, purpose, version, wrapped_key, kek_version)`. Ротация KEK —
  перезавернуть DEK, данные не трогаем; ротация DEK — фоновая перешифровка портала.
- Шифруются поля, по которым не фильтруем: сумма, базы и суммы налога, контрагент (имя, NIF), описание,
  заметки, IBAN реквизитов, вложения (чеки, фактуры — шифруются перед записью в storage). В открытом
  виде только то, что нужно для выборок и индексов: портал, период (дата), категория, направление,
  валюта, источник, статус.
- Отчёты считает сервер: читает период, расшифровывает в памяти, агрегирует. Объёмы (тысячи проводок в
  год на портал) это позволяют; кэш агрегатов — только по месяцам закрытых периодов, тоже шифрованный.
- Чего не делаем в логах, событиях и уведомлениях: сумм и контрагентов. Событие `finance.*` несёт только
  id, период и категорию. Swagger-примеры без сумм.
- Доступ: `finance.read` / `finance.write` остаются; добавляется `finance.admin` (реквизиты, налоговый
  профиль, закрытие периода, экспорт) — по умолчанию только owner/admin. Каждое чтение отчёта и экспорт —
  событие `finance.accessed` (журнал TASK-782).
- Бэкапы БД — шифрованные (TASK-789). Переход на E2E-«сейф» (ключ у владельца, сервер видит только
  шифротекст) — отдельно, TASK-802: модель данных уже хранит шифрованные поля как непрозрачные blob'ы
  с `scheme`/`key_version`, поэтому смена владельца ключа не меняет схему.

Signal-протокол здесь не нужен: он для переписки двух устройств (ratchet), а не для общего реестра.
Опыт из Sociopath (`libsignal-protocol-typescript`) пригодится в Inbox (TASK-786), если понадобится E2E чат.

## Доменная модель (один код для клубов и студий)

```
OrganizationProfile  1:1 Portal — юрлицо и фискальный профиль (TASK-796)
TaxRate              справочник ставок портала (TASK-797)
Product.taxRateId, priceIncludesTax; OrderItem: netAmount, taxRate, taxAmount; Order.taxTotal (TASK-797)
FinanceCategory      дерево «доходы / расходы», у категории код счёта (план счетов PGC упрощённый)
Counterparty         контрагент: имя, NIF, страна, тип (поставщик / клиент / участник / сотрудник / госорган)
LedgerEntry          проводка v2 (заменяет FinancialTransaction): дата, направление, категория, контрагент,
                     нетто, налог (ставка, сумма, вид IVA/IRPF-удержание), брутто, способ оплаты, счёт
                     (касса / банк), документ (номер, дата, тип: фактура выданная / полученная / чек / без
                     документа), источник (order, membership_fee, manual, import, stripe), вложения,
                     период, статус (draft / posted / void)
FinancePeriod        месяц/квартал портала: open / closed; закрытие замораживает проводки
Budget, BudgetLine   план расходов и доходов по категории на месяц (TASK-800)
InvoiceSeries, Invoice  фактуры выданные с нумерацией серии (TASK-801)
```

Под капотом проводка двусторонняя (счёт дебета / кредита из категории и способа оплаты), в UI —
«Доход / Расход / Перевод между счетами». Это даёт совместимость с PGC для SL и нормальный баланс кассы и
банка, не показывая бухгалтерию тем, кому она не нужна.

Клуб: доходы — членские взносы (cuotas), аportaciones по заказам, прочее; расходы — аренда, закупки,
зарплаты, услуги. Студия: доходы — услуги (запись TASK-755), товары, предоплата (TASK-758); расходы те же
плюс расходники и профессионалы с удержанием IRPF.

## Налоги и отчётность: что считаем, кому отдаём

Фискальный профиль портала задаёт страну и режим; цифры считаются одинаково, а «раскладка по формам» —
пресет страны. Первая страна — Испания; другие страны ЕС — свои пресеты позже, без переделки ядра.

| Форма организации | Режим по умолчанию                                                 | Отчёты и формы (цифры для gestor, не подача)                                                                                                                                                           |
| ----------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Asociación (клуб) | IVA: exento / no sujeto по настройке; IS с частичным освобождением | Книга доходов и расходов по статьям, баланс кассы, годовой отчёт для asamblea; Modelo 200 если доходы > 75 k € или есть облагаемая деятельность; 347 (контрагенты > 3 005,06 €); 111/190 при зарплатах |
| Autónomo (студия) | IVA general 21 %, estimación directa simplificada                  | Libro de ingresos, gastos, bienes de inversión; 303/390 (IVA), 130 (IRPF квартал), 111/190 (удержания), 347                                                                                            |
| SL (студия)       | IVA general, IS 25 %                                               | Libro diario из двусторонних проводок, 303/390, 200, 111/190, 347                                                                                                                                      |

Правила ставок и порогов, сроки форм и исключения — сверить с gestor перед релизом каждой формы;
в коде они лежат в пресете `es.ts`, не в бизнес-логике. Подача в AEAT, Verifactu и SII — отдельная
фаза (решение 7 в [verticals-and-seo](verticals-and-seo.md): после первых платящих студий; сроки
Verifactu 2027, возможно 2028).
