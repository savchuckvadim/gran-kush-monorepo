## A. Фильтр сущностей — P0

### TASK-601: концепция и общий компонент `EntityFilter` `[ ]`

Один компонент в `apps/crm/modules/shared/ui/EntityFilter`, который получает описание полей
сущности и отдаёт объект фильтра; `MemberList` и `OrdersTable` переводятся на него.

- **Свёрнутое состояние** — одна строка высотой с поисковую строку (чуть ниже шапки): поле
  «Искать…» + чипы активных условий + кнопка-иконка «поля». Занимает одну строку и на телефоне.
- **Развёрнутое** — под строкой полупрозрачная панель (стекло по токенам темы) с полями сущности,
  по которым можно отсеять: не больше **10 одновременно**, остальные — через «ещё…» с поиском по
  названию поля. Источник — `GET /crm/entity-fields/:code/filter-fields` (у поля `showInFilters`).
- **Два способа отсеять**: просто писать в строку (поиск по содержимому полей) и выбирать по полям
  (селекты — выбранное значение, текстовые — «содержит», числа и даты — диапазон).
- Выбранные условия — чипы в строке с крестиком; «Очистить всё» — в панели.
- Состояние фильтра — в URL (`?q=&f.status=&f.city=`), чтобы ссылка на отфильтрованный список
  работала и «назад» возвращал фильтр.
- **Дизайн по темам**: панель и чипы на `data-slot="filter"` / `filter-chip`, стили в
  `packages/ui/src/styles/skins.css`, как у `card`, `button`, `sidebar-link`. PafPaf — стекло и
  пилюли, Infierno/Grind — плоские, Clásico — как есть.
- Мобильный: строка остаётся, панель открывается на весь экран снизу (sheet).

### TASK-602: API фильтрации по содержимому `[ ]`

- Сейчас в списках только `filterFieldKey` + `filterValue` с точным равенством. Нужен общий
  контракт для всех списков сущностей: `q` (строка, поиск по значениям текстовых полей и системным
  колонкам) + `filters[fieldKey]=value|a..b|v1,v2`.
- Один `@Query()` DTO на хендлер (`IntersectionType(PaginationDto, EntityFilterDto)`), правило из
  CLAUDE.md.
- Для текста — `contains` без учёта регистра по `valueJson` (Postgres `ILIKE` на `valueJson::text`
  или по индексу — замерить на 10k участников); для селектов — `in`; для чисел/дат — диапазон.
- Поиск `q` можно собрать на базе `CrmSearchRepository.searchMembers` (Ctrl K), чтобы логика
  была одна.
- e2e: изоляция портала при поиске по полю (клуб A не видит B), совпадение по подстроке,
  неизвестный `fieldKey` → 400.

### TASK-611: ссылка с предзаполнением из формы нового участника `[ ]`

- В форме «Новый участник» (`features/members/create-member-form.tsx`) — иконка «открыть как
  ссылку в новой вкладке» рядом с заголовком. По нажатию создаётся ссылка регистрации, в которую
  зашито то, что уже ввели (email и поля формы), и открывается в новой вкладке.
- Как передавать предзаполнение: не в URL (персональные данные в адресной строке и в логах), а в
  самой ссылке — `RegistrationLink.prefillJson` (новое поле), публичный `GET /public/reg-links/:token`
  отдаёт его вместе со схемой; форма `join/[token]` в кабинете заполняет поля.
- Такая ссылка одноразовая по умолчанию (`maxUses = 1`), с `kind = personal`, именем
  «Для {имя или email}» и сроком жизни по настройке (по умолчанию 7 дней).

### TASK-612: диалог выданных ссылок `[ ]`

- Иконка-шестерёнка рядом с кнопкой выдачи открывает модалку: постранично (`GET` с
  `page/pageSize`) все ссылки портала.
- Колонки: название, тип (публичная / планшет / персональная), **статус** (готовится, готова,
  истекла, исчерпана, отозвана), использований / лимит, **сколько сейчас смотрят**, создана кем и
  когда, действия: копировать, QR, открыть, **отозвать** (с подтверждением, как в April —
  повторный клик за 3 с).
- Статусы считаются на бэке и отдаются полем `status` в `RegistrationLinkDto`; «готовится» —
  пока QR/короткая ссылка генерируются (если делать асинхронно; иначе статуса нет).
- Онлайн-просмотры: по образцу `SharePresenceService` из April — Redis ZSET
  `reglink:online:{token}`, heartbeat с публичной страницы `join/[token]` раз в 30 с
  (`POST /public/reg-links/:token/ping`), `leave` на `pagehide`. В диалоге обновлять раз в 15 с,
  пока он открыт.
- Фронт берём с April (`front/apps/kpi-sales/modules/feature/report-links/ui`): `ShareLinksDialog`,
  `ShareLinkBadges`, `ShareLinkUrlField` — переносить как компоненты в `apps/crm/modules/features/registration-links`,
  переписав под `@workspace/ui` и i18n (ru/en/es).
- Текущая страница в Настройках остаётся, но переводится на тот же диалог/список.
