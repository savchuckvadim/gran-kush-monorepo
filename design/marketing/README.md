# PafPaf и Nagual — прототип сайтов продукта

Статичный прототип продающих сайтов CRM для клубов: два сайта и шесть тем на одной разметке.
Это не код приложения. Где будет жить сайт, решаем отдельно (TASK-406 в
`documentation/tasks/rebranding-and-positioning.md`: `apps/marketing`, роуты в `apps/web` или
отдельный домен).

Открыть: `index.html` в Chrome (лучше через локальный сервер). Панель внизу слева:

- «Sitio» — PafPaf или Nagual;
- ☀ / ☾ — светлая или тёмная версия сайта;
- «Temas» — остальные направления;
- ES / RU — язык.

## Два сайта

| | PafPaf | Nagual |
|---|---|---|
| Бренд | в логотипе `paf paf` (две затяжки), в тексте PafPaf, домен `paf-paf.app` (куплен) | NAGUAL — отдельный бренд: лекарь, зелёная магия (`nagual.club`) |
| Режимы | светлый (по умолчанию) и тёмный | тёмный и светлый «зелёный на белом» |
| Стиль | минимализм в духе SmokApp: белый фон, крупные скругления, гротеск Onest | Cormorant Garamond, сакральная геометрия, споры |
| Эффекты | рамки с перетекающим градиентом (как в React Bits), фиолетовый дым в карточках, живые карточки в hero, кольцо на главной кнопке | те же приёмы в нефритовой палитре, зелёный дым |
| Hero | «Todo el humo. Cero papeleo.» | «Sana el caos de tu club.» |

Сначала публикуем один сайт. Второй лежит в репо и включается атрибутом `data-dir` на `<html>`.
Режим задаёт `data-mode="light|dark"`.

## Направления как темы

Каждое направление — набор токенов на `:root[data-dir]`: цвета, шрифты, радиусы, фильтр видео,
цвета дыма. Плюс несколько правил на классы. Тот же приём, что `@workspace/themes` в divan-shop.

Решение: все направления остаются темами.

- **CRM.** Пользователь выбирает тему. Текущая тема CRM остаётся темой по умолчанию.
- **Портал клуба.** Получает свою тему (поля бренда портала — TASK-410).
- **Форма регистрации нового участника.** Тему настраивает менеджер.

Прототип тем CRM с той же идеей лежит в `../crm-themes/`.

## Дальше: сайты на Payload (предложение, не решение)

Нужно, чтобы тарифы, контакты и тексты правились без программиста и на всех языках. Предлагаем
тот же стек, что в divan-shop.

- **Приложение.** Новое `apps/site` в этой монорепе: Next 16 + Payload 3. Админка `/admin` есть
  только в сборке PafPaf. Так решается TASK-406: отдельное приложение (вариант A), у каждого сайта
  свой домен (вариант C).
- **Языки.** ru, en, es, как в CRM (`apps/crm/i18n.ts`). Тексты интерфейса — в типизированных
  словарях, контент — в локализованных полях Payload.
- **Два сайта — один код.** Сайт выбирается при сборке: `NEXT_PUBLIC_SITE=pafpaf|nagual`. Коллекция
  `sites` хранит домен, тему, hero, слоган и контакты каждого сайта. База и админка общие.
- **Что в Payload.** Страницы, гайды блога, FAQ, функции, допы, контакты, соцсети, SEO.
- **Тарифы.** Цена и период берутся из `BillingPlan` в API, по нему CRM и выставляет счёт. В Payload
  лежат только тексты тарифа по его `code`: название, описание, пункты, бейдж. Так цена на сайте не
  разойдётся со счётом. Для этого нужен публичный эндпоинт со списком активных тарифов, сейчас его
  в API нет.
- **База.** Payload получает отдельную базу на том же сервере Postgres, а не схему Prisma. Тогда
  миграции Payload и Prisma не мешают друг другу.

## Что внутри

- **Hero.** Видео на весь экран под прозрачной шапкой. Поверх — WebGL-дым, который тянется за
  курсором (`fluid.js`, по мотивам WebGL Fluid Simulation, MIT). У PafPaf и Nagual справа три
  живые карточки: «сейчас в клубе», выдача, QR участника.
- **Липкая навигация.** Плашка перетекает к выбранному пункту, частицы склеиваются фильтром goo
  (по мотивам GooeyNav из React Bits).
- **Перетекающие рамки** (`.flow`). Conic-gradient в `border-box` и анимируемый `@property --angle`.
  Стоят на демо, окне CRM, рекомендованном тарифе и финальном призыве.
- **Дым в карточках** (`.card__smoke`). Видео грузится, только когда карточка в зоне видимости, и
  ставится на паузу вне её. Цвет задаёт `--card-smoke`.
- **Живая демо-песочница.** Скан QR → карточка участника (поручитель, взнос, возраст) → выдача с
  проверкой месячного лимита → чек со складом.
- **Функции, панель и происхождение.** Функции в сетке-бенто, панель CRM и телефон с QR участника
  (пример данных), блок «Мы появились внутри клуба в Торревьехе».
- **Цены и заказы.** Калькулятор цены по числу участников, «месяц / год», НДС 21 %. Корзина с
  допами, оформление (CIF ассоциации, Stripe — макет), «Мои заказы».
- **Блог** (гайды), **FAQ**, финальный призыв.
- **Входы.** «Войти в CRM» — для команды клуба, «Я участник» — в кабинет участника.

Цены и тексты про пробный период — примеры прототипа, не решение.

## Видео

`assets/*.mp4` — бесплатные клипы Mixkit (лицензия Mixkit: коммерческое использование без
атрибуции):

- `hero-smoke` — https://mixkit.co/free-stock-video/a-trail-of-smoke-rapidly-twirls-over-a-dark-background-50951/ (hero и дым в карточках);
- `smoke-portrait` — https://mixkit.co/free-stock-video/swirling-smoke-with-black-background-1965/ (hero на телефоне).

Видео с людьми не используем.

Для продакшена: перекодировать в 1080p AV1/H.264 примерно на 2–3 МБ, цикл 8–10 с, свой постер
как LCP.

## Для продакшена (SEO first)

- Весь текст в HTML. Видео и WebGL — украшение поверх постера: `preload="metadata"`, запуск после
  загрузки, выключение при `prefers-reduced-motion`.
- Шрифты через `next/font` с подогнанным запасным шрифтом. Без этого огромные заголовки дают сдвиг
  макета при подмене шрифта.
- Реклама каннабис-тематики в Google и Meta запрещена. Рост — через SEO: гайды, глоссарий,
  страницы по регионам, каталог клубов (`/clubs`, TASK-409). Два сайта ведут в одну CRM, поэтому
  у каждого свой контент и своя аудитория, а не копия текстов (иначе Google сочтёт их дорвеями).
